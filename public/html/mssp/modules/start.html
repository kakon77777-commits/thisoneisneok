從這裡開始

這個方法要解決什麼

一個專案剛開始的時候，你可以在腦中裝下它的全部。哪個檔案做什麼、改動這裡會影響哪裡、哪些規則不能違反——這些都還在你的工作記憶裡。

這個狀態會結束，而且結束得比大多數人預期的早。當專案同時具備多個角色、多個外部工具、不同風險等級、數十種子任務、可替換的領域能力與長期維護時，「我知道這個系統」會悄悄變成「我知道我上次改過的那部分」。

MSSP（母集與子集範式，Mother-Set and Subset Paradigm）處理的是這個轉折點之後的事：

不是把程式切碎，而是讓狀態的邊界可以被看見與操作。

它換到什麼

這不是抽象的好處。以下每一項都來自001 號範例實際做出來的效果：

能力可以被單獨載入與測試。 註冊表讓「建立一個只有一個模組的系統」在程式上可以構造，於是孤島測試成為一個可以執行的檔案，而不是一句宣稱。「這個模組是獨立的」從此是一個會失敗的斷言。

新增能力不必動核心。 兩個報表模組共用 SMS 持有的契約，任何一個都可以單獨刪掉或替換，另一個不受影響。加第三個報表也不需要改核心。

權限成為可檢查的東西。 把限制寫成函式而不是註解之後，執行器可以在任何處理器跑起來之前擋下路徑穿越。註解做不到這件事。

架構可以被機器驗證。 「沒有任何 TMS 引用兄弟 TMS」不靠人眼審查，build-mssp.mjs 會 grep 並讓 build 失敗。結構從一個習慣變成一個約束。

上下文變成可調度的資源。 對 Agent 而言這是最直接的收益：一個只需要其中一項能力的任務，不必讀完所有規則，也就不會被無關規則誤導。

五個集合

它們是角色，不是強制要建的目錄。

FMS — 這個系統是什麼、為何存在、東西在哪裡。純元資料，零執行邏輯。它同時服務人類與要載入這個系統的 Agent。

SCL — 什麼可以被改變、由誰改、在什麼風險等級下改。存在的理由是知識與權限是兩件事：一個模組可以完整描述如何刪除正式資料，同時不擁有刪除的權限。

SMS — 移除之後，系統就不再是原本那個系統的能力。

TMS — 按需載入、可替換、可以單獨測試的能力。

DMS — 人類能看見系統實際做了什麼。

兩個問題決定位置

  1. 移除它之後，系統的核心任務還能不能閉環？ 不能 → SMS。能 → TMS。
  2. 只載入最小核心、其他 TMS 都不在的情況下，它能不能被測試？ 不能 → 還有隱藏耦合要處理。

第一個問題最常見的誤答是把「很常用」當成「不可缺少」。一個到處在寫日誌的任務執行器，刪掉日誌仍然是任務執行器；刪掉排程就不是了。

不確定的時候放 TMS。之後升成 SMS 是一次受控的改動。

依賴規則

TMS-A  →  SMS 共享契約  ←  TMS-B

兩個 TMS 需要合作時透過 SMS 持有的介面，而不是直接互相 import。這條規則可以機械檢查：對一個 TMS grep 有沒有引用兄弟 TMS 的路徑。

001 號範例整篇就在講這一行 import。

度：你的專案該用多少

這是整個方法最實用的部分，也是這個專區要示範的主題。MSSP 不是全有全無。 挑選你這個規模真的換得到東西的集合。

規模 徵狀 用哪些
小 一個任務、一個工具或沒有工具、沒有高風險操作 單一檔案 + 測試。這時候保持簡單就是正確答案
中 數個相關任務、二到五個工具、有平台差異、設定值得驗證 FMS + SMS + TMS。權限真的需要強制時再加 SCL，執行結果不再一目瞭然時再加 DMS
大 下列多項同時出現 五個集合 + Router

「大」的訊號（要多項同時出現，不是只有一項）：超過三種角色、超過五個外部工具、超過十個子能力、唯讀與寫入並存、存在不可逆動作、不同任務需要的上下文真的不同、多平台適配、多人或多 Agent 協作、子能力需要獨立測試、一份文件已經無法在幾分鐘內說清楚整個系統。

升級是漸進的，不需要一次到位。 從 FMS 開始（它最便宜，而且立刻有用），需要的時候再加下一個集合。一個只有 FMS + SMS + TMS 的中型專案，是完全正常的 MSSP 專案。

判斷有沒有加對的方法很簡單：這個集合有沒有讓某件原本做不到的事變得可以做？ 有，就留著。沒有，就先拿掉，等它需要的時候再回來。

為什麼在 Agent 時代這件事變重要

當系統的一部分是會讀取上下文並自己決定要做什麼的 Agent 時，多出一個稀缺資源：上下文本身。它有容量、有成本、有注意力競爭、有污染風險。

上下文效用密度：

ρq=Itask relevantIloaded\rho_q = \frac{I_{\text{task relevant}}}{I_{\text{loaded}}}ρq​=Iloaded​Itask relevant​​

理想是 ρq→1\rho_q \rightarrow 1ρq​→1 。全量注入會讓 ρq\rho_qρq​ 隨系統規模單調下降；按需載入讓它保持穩定。MSSP 在這裡的作用，是讓「只載入真正需要的子集」從願望變成結構性質。
