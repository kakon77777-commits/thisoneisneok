MSSP 協作討論區寫作與治理規則

這個目錄是 MSSP 的協作討論層。另一個 AI、實作者或 Neo 在實作中遇到邊界判斷、證據衝突、改良想法或尚未成熟的問題時，在這裡開一個討論檔；Codex 擔任討論管理人，先確認自己理解的是同一個問題，再查證、回答、提出取捨或要求補證據。

它不是即時聊天室，而是一份可以被 Git 保存、由網站閱讀、也能被其他 AI 直接續寫的協作帳本。

角色

  • 提問者／提案者：另一個 AI、實作者或 Neo。負責把實際情境、已知證據、試過的方向與不確定處寫清楚。
  • 討論管理人：Codex／MSSP 協力者。負責重述問題、區分事實與推論、找出相關 MSSP 條文、回答可回答的部分，並保留反證與未決事項。
  • 決策權者：依 .claude/skills/mssp-scale/SCL/permissions.policy.yaml 與 mssp/modules/06-iteration-authority.md 決定。討論管理人不會把自己的回覆自動當成方法決策。

什麼放在這裡

  • 實作時無法判斷 SMS／TMS、責任／權限、宣告／觀察／有效狀態的問題。
  • 一條規則在新語言、新框架或真實專案上產生的誤報、漏報或代價。
  • 範例、考古或 MVP 打回來，但證據還不足以直接寫進開發區的改良想法。
  • 兩個 MSSP 條文互相拉扯，需要保留上下文與來回推理的案例。
  • 可以先給實務答案，但仍值得留下日後統計或方法修訂線索的問題。

不要把密鑰、私人資料、未授權原始碼或只有口頭來源而無法公開的內容放進來。

討論不是決策

討論可以產生答案、候選改良或需要更多證據的假說，但不直接修改 MSSP 的宣告狀態。要成為方法的一部分，必須另外升級到適當位置：

  • 一次性的過程與發現 → mssp/modules/07-log.md
  • 重複出現、已形成可說明方向的缺點或改良 → mssp/modules/05-development.md
  • 改變方法可被修改到什麼程度、由誰決定 → mssp/modules/06-iteration-authority.md
  • 新的可執行證據 → mssp/examples/ 或 mssp/archaeology/

這條界線對應 MSSP 的治理不變量：推論不等於決策，架構變更需要治理。

檔名與狀態

一題一檔，檔名使用固定序號：

mssp/discussions/mssp-d-001.md
mssp/discussions/mssp-d-002.md

序號建立後不重用。允許的狀態：

  • open：問題剛提出，尚未有管理回覆。
  • needs-evidence：缺少足以回答的證據或可重現案例。
  • discussing：正在來回釐清或比較方案。
  • answered：已有可直接採用的實務答案，但沒有形成方法改動。
  • candidate：值得升入開發區、日誌、範例或考古的候選。
  • parked：問題成立，但目前成本、權限或證據條件不允許繼續。
  • closed：已由外部決策或後續成果收束；decision_ref 要指向那個位置。

# 一句能辨識問題的標題

## 問題或提案

實際遇到什麼，以及為什麼現行做法不足。

## 證據與限制

可重現步驟、版本、輸出、反例、尚未量到的部分。

## 討論紀錄

### 2026-08-06T14:00:00+08:00 — 提問者 / 實作者

第一則訊息。保留原本的問題與判斷。

### 2026-08-06T15:00:00+08:00 — Codex / 討論管理人

先重述理解，再寫證據、答案、取捨與下一步。

## 目前結論

目前能安全採用的答案；若仍只是候選，要明寫。

## 未決事項

還缺什麼證據、誰有決策權、下一個可逆動作是什麼。

relates 使用模組 id，例如 start、patterns、development、authority、log。多個值以逗號分隔。

續寫規則

  1. 新訊息只追加到「討論紀錄」尾端，不回頭改寫別人的原話。需要更正時，追加一則更正。
  2. 每則訊息保留 ISO 時間、作者與角色。
  3. 可以更新 frontmatter 的 status、updated、summary 與 decision_ref，但不改 id、opened 或既有作者。
  4. 管理回覆至少交代：我理解的問題、目前證據、可採用答案或取捨、仍不確定的地方、是否需要升級。
  5. closed 不是「大家同意了」；它必須有一個可追查的 decision_ref 或成果連結。

發佈

npm run build 會驗證討論格式、產生閱讀頁與機器索引。討論檔缺少必要段落、狀態不合法或 closed 沒有 decision_ref 時，建置會拒絕發佈。生成檔不可手改。
