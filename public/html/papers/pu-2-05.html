可編譯世界：程式執行作為世界狀態差分

The Compilable World: Program Execution as Governed World-State Difference

論文編號： PU-2-05

作者： Neo.K with Aletheia
機構： EveMissLab／一言諾科技有限公司

摘要

前四篇依序建立：程式語言不等於文字；符號應被理解為受治理算子；程式語言具有語法、語意與效果三層；自然意圖需要先進入意圖中介表示，再生成多重可執行投影。本篇進一步處理最終執行問題：當一個已驗證的意圖 IR 取得執行權後，Runtime 真正做的事情是什麼？

本文提出：

Program Execution≠Instruction Consumption\boxed{ \text{Program Execution} \neq \text{Instruction Consumption} }Program Execution=Instruction Consumption​

並將程式執行重新定義為：

在明示世界模型、權限、規則與證據條件下，提出、驗證、提交、觀測並核對一項世界狀態差分。

形式上：

CompileWorld:(Wt,IR,Γ,P)→⟨ΔW^,Plan,Obligations,Guards⟩\boxed{ CompileWorld : \left( W_t, \mathcal I_R, \Gamma, P \right) \rightarrow \left\langle \widehat{\Delta W}, Plan, Obligations, Guards \right\rangle }CompileWorld:(Wt​,IR​,Γ,P)→⟨ΔW,Plan,Obligations,Guards⟩​

其中：

  • WtW_tWt​ ：執行前世界狀態；
  • IR\mathcal I_RIR​ ：已結構化意圖；
  • Γ\GammaΓ ：語意、型別、規則與 Runtime 環境；
  • PPP ：權限與委任；
  • ΔW^\widehat{\Delta W}ΔW ：預測世界差分；
  • PlanPlanPlan ：可執行計畫；
  • ObligationsObligationsObligations ：證據、補償、通知與人類決策義務；
  • GuardsGuardsGuards ：狀態、不變量、資源與安全守衛。

真正提交則為：

CommitWorld:(Wt,ΔW^,Plan,P)→⟨Wt+1,Events,Evidence,Residual⟩\boxed{ CommitWorld : \left( W_t, \widehat{\Delta W}, Plan, P \right) \rightarrow \left\langle W_{t+1}, Events, Evidence, Residual \right\rangle }CommitWorld:(Wt​,ΔW,Plan,P)→⟨Wt+1​,Events,Evidence,Residual⟩​

本文核心命題是：

ΔW^≠ΔW\boxed{ \widehat{\Delta W} \neq \Delta W }ΔW=ΔW​

預測差分不等於實際世界差分。模型所預測的狀態變更、外部效果與受影響主體，可能因：

  • 世界狀態已變；
  • 外部服務失敗；
  • 物理設備未響應；
  • 訊息重複或延遲；
  • 權限被撤銷；
  • 規則版本改變；
  • 人類拒絕；
  • 模型遺漏；

而與實際結果不同。

本文因此建立世界提交六階鏈：

Propose→Validate→Authorize→Commit→Observe→Reconcile\boxed{ Propose \rightarrow Validate \rightarrow Authorize \rightarrow Commit \rightarrow Observe \rightarrow Reconcile }Propose→Validate→Authorize→Commit→Observe→Reconcile​

其中：

  1. Propose：由 IR 建立候選世界差分；
  2. Validate：檢查前置狀態、不變量、版本、資源與規則；
  3. Authorize：確認主體、委任、批准與作用域；
  4. Commit：實際改變權威數位狀態或發出外部作用；
  5. Observe：收集事件、回執、感測與人類回應；
  6. Reconcile：比較預測與實際差分，處理未知、部分成功與殘差。

本文將可編譯世界表示為：

W=⟨E,S,R,A,B,H,X,O⟩\boxed{ W = \left\langle E, S, R, A, B, H, X, O \right\rangle }W=⟨E,S,R,A,B,H,X,O⟩​

其中：

  • EEE ：Entities，具有身份的世界實體；
  • SSS ：States，權威狀態與局部狀態；
  • RRR ：Rules，合法轉移與不變量；
  • AAA ：Actors，行動者、批准者與受影響者；
  • BBB ：Boundaries，責任、權限與系統邊界；
  • HHH ：History，事件、版本與承諾歷史；
  • XXX ：Externalities，外部數位、制度與物理世界；
  • OOO ：Observability，可取得證據與未知範圍。

一個世界能被編譯，不表示世界可被完全計算。本文所謂「可編譯」，是指世界中至少有一部分狀態、規則、權限、效果與證據可被結構化，使候選差分能在提交前被檢查，在提交後被觀測與核對。

本文提出：

Compilable≠Fully Predictable\boxed{ \text{Compilable} \neq \text{Fully Predictable} }Compilable=Fully Predictable​

外部世界、社會制度與物理環境具有不可完備觀測、延遲、他者意志與隨機性。可編譯世界的成熟性不在於消除未知，而在於把未知、不可觀測與不可控制邊界正式寫入執行模型。

本文區分四種世界差分：

  1. 內部計算差分：記憶體、值與暫時結構；
  2. 權威數位差分：資料庫、身份、狀態機與事件歷史；
  3. 制度差分：權限、責任、承諾、批准與法律地位；
  4. 物理差分：設備、位置、能源、物體與人體狀態。

四者的提交、觀測與可逆性不同。內部計算可能可自由重跑；權威數位狀態需交易與版本；制度差分需要合法主體與程序；物理差分則必須依賴感測、現場安全與不可逆風險治理。

本文提出世界差分判定：

Γ;Wt;P⊢ΔW:Legal!ϵ▹O\Gamma;W_t;P \vdash \Delta W : Legal ! \epsilon \triangleright OΓ;Wt​;P⊢ΔW:Legal!ϵ▹O

表示在環境 Γ\GammaΓ 、世界狀態 WtW_tWt​ 與權限 PPP 下，差分 ΔW\Delta WΔW 合法，具有效果簽章 ϵ\epsilonϵ ，並產生觀測與證據義務 OOO 。

本文進一步建立「世界交易」概念。傳統資料庫交易主要維持資料一致性；世界交易則需同時處理：

  • 權威狀態；
  • 外部事件；
  • 物理效果；
  • 人類承諾；
  • 部分成功；
  • 結果未知；
  • 補償；
  • 證據；
  • 使用者接受。

形式上：

WorldTransaction=StateTransition+ExternalEffects+EvidenceObligations+ResidualGovernance\boxed{ WorldTransaction = StateTransition + ExternalEffects + EvidenceObligations + ResidualGovernance }WorldTransaction=StateTransition+ExternalEffects+EvidenceObligations+ResidualGovernance​

本文特別區分「提交」與「完成」。本地資料庫寫入成功，只能證明局部提交；外部 API 接受，只能證明外部系統已受理；感測器確認，只能證明某一物理訊號；最終完成還可能需要人類接受、制度確認或長時程觀測。

因此：

Committed⇏Completed⇏Accepted\boxed{ Committed \not\Rightarrow Completed \not\Rightarrow Accepted }Committed⇒Completed⇒Accepted​

本文也提出「世界版本」與「差分衝突」。意圖 IR 可能基於 WtW_tWt​ 生成計畫，但執行時世界已進入 Wt+kW_{t+k}Wt+k​ 。Runtime 必須檢查：

Version(Wplanned)=Version(Wcurrent)Version(W_{\mathrm{planned}}) = Version(W_{\mathrm{current}})Version(Wplanned​)=Version(Wcurrent​)

或重新評估差分是否仍合法。這使 optimistic concurrency、狀態版本、因果時鐘與人類再確認成為世界編譯的一部分，而不是只屬於資料庫技術。

本文進一步處理模擬、dry-run、沙盒、分階段提交、兩階段批准、補償、重建與回放。模擬可以預測，但不能替代真實世界證據；dry-run 可以揭露預期差分，但不能保證外部世界不變；沙盒可以限制能力，但若仍可呼叫外部網路、產生費用或改變治理狀態，就不是真正效果沙盒。

本文使用檔案修改、資料庫遷移、訂單付款、網站部署、AI Agent 多工具執行、研究發布與物理設備控制等案例，說明世界差分如何被提出、驗證、提交、觀測與核對。本文最後提出可證偽研究綱領，包括預測—實際差分誤差、提交—完成落差、世界版本衝突、外部效果證據率、部分成功治理、物理效果確認、世界交易恢復率、沙盒效果洩漏及 AI Agent 差分預覽對事故率的影響。

本文為第 2 冊最後一篇〈後文本程式語言〉建立執行地基：當語言能表示意圖、算子、語意、效果與世界差分後，下一步就是統合文字、視覺、自然語言、驗證、Runtime 與物理耦合，形成後文本程式語言的完整框架。

Abstract

This paper redefines program execution as the governed proposal, validation, authorization, commitment, observation, and reconciliation of a world-state difference.

A compilable world is not a fully predictable world. It is a world in which enough entities, states, rules, permissions, effects, and evidence obligations are structured to support pre-execution validation and post-execution reconciliation.

The paper distinguishes predicted and actual world differences, local commitment and final completion, digital, institutional, and physical effects, world transactions, version conflicts, partial success, residuals, and evidence obligations.

Keywords: compilable world, world-state difference, world transaction, runtime, effect commitment, physical coupling

一、問題的提出：程式執行到底發生了什麼

傳統敘事常說：

CPU 執行指令。

這在機器層正確，但對系統層不完整。

使用者真正關心的不是：

  • 哪個 opcode 被執行；
  • 哪個暫存器改變；
  • 哪個函式回傳。

而是：

  • 文件是否真的修改；
  • 付款是否真的完成；
  • 網站是否真的公開；
  • 權限是否真的撤銷；
  • 機器是否真的啟動；
  • 受影響者是否真的收到結果。

因此，程式執行必須被提升為世界差分問題。

3.1 可編譯

若世界中的某一部分具有：

  • 可識別實體；
  • 可表示狀態；
  • 明示規則；
  • 可判定權限；
  • 可描述效果；
  • 可取得證據；

則候選差分可以被編譯與驗證。

每一重要效果應定義：

  • 成功證據；
  • 失敗證據；
  • 結果未知證據；
  • 人類接受；
  • 保存期限。

10.4 殘差治理

世界交易可能無法完全達到預測差分，需保存：

  • 未完成；
  • 不可逆；
  • 補償中；
  • 爭議；
  • 外部待確認；
  • 模型外影響。

10.5 資料庫交易只是子集

資料庫原子性、隔離性與持久性非常重要，但不能包住所有外部、制度與物理效果。

十一、提交、完成與接受

11.1 Committed

權威系統已接受並保存差分，或外部命令已正式送出。

11.2 Completed

所有必要狀態、外部效果與證據義務已達成。

11.3 Accepted

合法主體或制度已接受結果，必要申訴與補救位置已滿足。

11.4 三者分離

Committed⇏Completed⇏Accepted\boxed{ Committed \not\Rightarrow Completed \not\Rightarrow Accepted }Committed⇒Completed⇒Accepted​

11.5 例子

付款請求已提交，不代表銀行已授權。

銀行授權完成，也不代表客戶爭議已結案。

部署已提交，不代表使用者旅程正常。

訊息已送達，不代表收件人已閱讀與接受。

十二、分階段提交

12.1 Prepare

建立候選差分、鎖定資源或保存檢查點。

12.2 Approve

由合法主體批准高風險節點。

12.3 Commit

正式修改權威狀態或啟動外部效果。

12.4 Verify

收集外部與 Runtime 證據。

12.5 Finalize

更新整體工作流為完成或接受。

12.6 優點

分階段提交可避免：

  • 一次性不可逆跳躍；
  • 舊批准套用新世界；
  • 低階成功冒充整體完成；
  • 無證據就關閉任務。

13.2 Dry-Run

執行真實解析、驗證與規劃，但阻止某些提交效果。

13.3 模擬價值

可提前發現：

  • 狀態衝突；
  • 權限不足；
  • 資源不足；
  • 影響範圍；
  • 不可逆節點；
  • 缺少證據。

13.4 模擬限制

模擬不能完整預測：

  • 真實網路；
  • 人類回應；
  • 外部制度；
  • 未知物理環境；
  • 並行世界行動。

13.5 Dry-Run 洩漏

若 dry-run 仍會：

  • 呼叫真實外部服務；
  • 寫入追蹤；
  • 產生費用；
  • 發出通知；
  • 修改配額；

它就不是零效果執行。

三十、主要失敗模式

  1. 執行即指令消耗： 忽略程式真正提交世界差分。
  2. 預測即真實： 將模型差分當成已發生效果。
  3. 可編譯即完全可控： 否認未知、他者意志與物理不確定。
  4. 世界狀態無版本： 使用舊狀態直接提交新差分。
  5. 資料版本即世界版本： 忽略規則、權限、外部與感測變化。
  6. 驗證後永久有效： 計畫執行時不重新檢查高風險守衛。
  7. 提交即完成： 本地寫入成功便關閉整體工作流。
  8. 完成即接受： 忽略人類、制度與申訴位置。
  9. 資料庫交易等於世界交易： 外部與物理效果被排除於一致性之外。
  10. 請求送出即外部成功： API 入列被當成外部完成。
  11. 命令送出即物理效果： 缺少感測確認。
  12. 數位紀錄即制度有效： 權限或批准缺少合法程序。
  13. Unknown 布林化： 結果未知被當成失敗或成功。
  14. 部分成功壓平： 多個子差分被單一狀態碼遮蔽。
  15. Dry-run 零效果迷思： 模擬流程仍產生外部呼叫、費用或紀錄。
  16. 沙盒只限制程序： 網路、金流、治理與物理效果仍可洩漏。
  17. 回滾刪除世界歷史： 忽略外部觀測與不可逆殘差。
  18. 補償冒充完全復原： 信任、時間、費用與資訊效果未被表示。
  19. 觀測不足仍宣稱核對： 只根據單一回覆判定世界完成。
  20. 額外效果不回饋： Runtime 發現未預測作用後仍繼續執行。
  21. 世界日誌只記技術細節： 無原始意圖、批准、責任與殘差。
  22. Agent 沿舊計畫前進： 世界偏離後不停止或重新編譯。
  23. 物理感測單點真相： 感測器故障未被交叉驗證。
  24. 研究發布等於研究成立： 發布效果與知識真值混淆。

三十一、可證偽研究綱領

31.1 預測—實際差分誤差

測量候選差分生成後，到實際提交前，世界、規則、權限與外部狀態改變的比例。

31.4 重新編譯效益

比較世界版本衝突後直接重試與重新建立 IR／差分計畫，對事故與錯誤提交的影響。

31.5 外部效果證據率

統計宣稱完成的 API、訊息、金流與發布效果中，有多少具有足夠外部回執與本地核對。

31.6 物理效果確認率

統計物理命令中，有多少具有感測確認、信心、時間與安全證據。

31.7 結果未知治理

研究正式 Unknown 狀態是否降低重複付款、重複通知與重複物理操作。

31.8 部分成功完整度

檢查多階段工作流是否能分別表示完成、失敗、未知、補償與人類接管。

31.9 世界交易恢復率

分別測量回滾、補償、重建與接受殘差後，世界狀態與責任是否真正閉合。

31.10 Dry-Run 效果洩漏

統計標示為 dry-run 或模擬的執行中，實際產生網路、費用、資料、權限或外部紀錄的比例。

31.11 世界沙盒完整度

比較程序隔離與效果沙盒，在限制資料、外部、物理與治理效果上的差異。

31.12 差分核對延遲

測量提交後多久能確認：

  • matched；
  • partial；
  • diverged；
  • unknown；
  • compensation-required。

31.13 額外效果發現率

測量 Runtime 觀測對未宣告寫入、網路、權限與物理效果的檢出能力。

31.14 AI 差分預覽效益

比較 Agent 直接執行工具計畫，以及先展示預測世界差分、權限、不可逆節點與恢復後的事故率。

31.15 制度差分有效性

統計數位批准紀錄中，有多少真正滿足合法主體、程序、生效時間與申訴要求。

31.16 世界日誌可重建性

檢查僅依世界差分日誌，能否重建意圖、批准、提交、證據、殘差與補償歷史。

31.17 物理模型殘差

測量設備控制中預測運動、能源與安全狀態和實際感測結果的偏差。

31.18 跨世界層教學實驗

比較只教授函式執行，以及同時教授內部、權威數位、制度與物理差分的學習者，在真實系統設計上的表現。

三十四、結論：Runtime 是世界差分提交器，不只是指令機器

在低階計算觀中，Runtime 讀取指令、配置資源、更新記憶體並輸出結果。

這個描述仍然成立。

但當程式進入資料庫、網路、制度、Agent 與物理設備後，Runtime 的責任已經超越指令調度。

它必須知道：

  • 目前世界版本；
  • 哪些狀態是權威；
  • 哪些規則仍有效；
  • 誰有權提交；
  • 哪些效果不可逆；
  • 哪些主體會受到影響；
  • 哪些證據代表外部完成；
  • 哪些結果仍未知；
  • 哪些殘差需要補償或接受。

本文因此將 Runtime 重新定義為：

Runtime=World-Difference Committer+Effect Observer+Residual Reconciler\boxed{ \text{Runtime} = \text{World-Difference Committer} + \text{Effect Observer} + \text{Residual Reconciler} }Runtime=World-Difference Committer+Effect Observer+Residual Reconciler​

World Compiler=Intent-to-Difference Planner+Legality Checker+Obligation Generator\boxed{ \text{World Compiler} = \text{Intent-to-Difference Planner} + \text{Legality Checker} + \text{Obligation Generator} }World Compiler=Intent-to-Difference Planner+Legality Checker+Obligation Generator​

Intent→Candidate Difference→Legal Commitment→Observed Difference→Reconciled World\boxed{ \text{Intent} \rightarrow \text{Candidate Difference} \rightarrow \text{Legal Commitment} \rightarrow \text{Observed Difference} \rightarrow \text{Reconciled World} }Intent→Candidate Difference→Legal Commitment→Observed Difference→Reconciled World​

這個結構也重新定位「成功」。

成功不再是函式沒有拋出例外，也不只是資料寫入完成。

成功至少需要回答：

預期世界差分是什麼？
實際發生了什麼？
哪些部分有證據？
哪些部分仍未知？
哪些額外效果出現？
哪些主體尚未接受？
哪些殘差仍需處理？

因此，世界編譯不是將現實幻想成完全可計算。

相反地，它要求系統對自己的不可完備保持誠實。

凡是不能控制的，必須標示外部。

凡是不能觀測的，必須標示未知。

凡是不能逆轉的，必須在提交前揭露。

凡是必須由主體選擇的，必須保留決策節點。

凡是已經改變世界的，都必須留下證據與責任。
