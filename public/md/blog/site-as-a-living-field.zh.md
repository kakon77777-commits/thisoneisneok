# 把個人網站改成仍在生活的場域

我最近重新整理了自己的網站分工。

這裡不需要再成為另一座龐大的論文庫。完整的理論語料、時間線與大量節點，本來就有 Logic Matrix 承擔。把它們再次搬到個人網站，只會讓卡片、分類、翻譯與版本維護不斷膨脹。

> 降低管理負擔，不代表降低內容密度；它代表讓不同內容回到真正適合它的容器。

## 這個網站保留什麼

新版個人網站只保留幾種會持續使用的內容：

- 個人部落格與每日文字記錄；
- 可以實際操作或展示的應用與實驗；
- MSSP 架構的教學、考古與參考實作；
- Lean4 驗證，以及理解驗證所必需的配套論文；
- 少量書籍與過去仍有展示價值的作品。

這樣一來，網站不必假裝自己是一套已完成的知識總庫。它更接近一個仍然會變動、會修正、會留下版本痕跡的個人場域。

## Markdown 是來源，HTML 與 PDF 是人類介面

每篇文章以 Markdown 保存。網站再由同一份來源生成：

1. 適合日常閱讀的 HTML 網頁；
2. 可以保存與列印的 PDF；
3. 保留原始 Markdown 的永久網址；
4. 給 AI 讀取的結構化索引。

因此，人類不需要面對原始文字檔，AI 也不必從裝飾性網頁反向猜測內容結構。

## 版本不再等於成熟

在 AI 可以不斷檢查、改寫與擴張文本的時代，「成熟」很可能只是暫時停止修改的名字。

所以這個網站更傾向標示版本、更新時間與生命週期，而不是宣稱某個項目已經終極完成。`Evolving`、`Prototype`、`Semi-stable` 比單一的「成熟／不成熟」更接近實際狀態。

網站從今天開始不再只是展示頁，而是新的記錄入口。
